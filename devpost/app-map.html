One action, three stops

When you select “Build my checklist,” your text travels through this route.

1. Find suggestions

dist/core.js → scan checks sentences for words such as deadline, eligibility, or repository. It retains the source wording.

2. Show the checklist

dist/app.js → render creates labeled controls and source details. Text is displayed as text, so pasted markup cannot become page code.

3. Remember progress

dist/app.js → save writes the current workspace to this browser's storage. Exporting makes a separate file you can keep.

A practice to reuse

Test a complete journey rather than only a button: enter rules, scan, review evidence, mark a requirement, reload, then inspect the exported file. Separate “the feature ran” from “the result is correct.”

Why a finding can be missing

The scanner looks for keywords. A rule expressed unusually can be missed. Add it manually and keep its evidence. A later semantic extractor would still need review.
